# Rinspace 表里世界实施任务

> 状态：任务 1–25 已于 2026-09-05 完成。当天完成生产纠偏：表世界恢复既有私有前端，仅上线独立世界导航；里世界完成品牌、头像和冷启动内容修复。写入、推荐和浏览量已开放；联邦继续关闭。

## 1. 执行原则

- 三个代码库各司其职：`rinspace-web` 发布世界契约、共享壳层和表世界；Rinspace Mastodon fork 实现里世界；私有 `rinspace` 负责同源网关、身份控制面、迁移和部署编排。
- 每次跨仓库发布都使用不可变提交或制品摘要，不消费工作树、浮动分支或未经记录的线上文件。
- 第一期严格本地：远端账号、远端帖子、联邦收发与发现必须在边缘、应用和网络出口同时关闭。
- `/p/:id` 是帖子的唯一稳定网页入口；slug 只用于可读性。旧式 `/@username/:statusId` 不兼容、不重定向。
- 每项任务完成时同时提交实现、自动化验证、必要文档和回滚说明；负责人可基于当前规模、内容边界和回退能力明确批准压缩观察窗口，但不得跳过制品校验、同源冒烟、数据备份或联邦关闭。
- 生产切换、数据迁移和公开发帖需要负责人明确授权；该授权已于 2026-09-05 给出并执行。

## 3. 任务清单

### 里程碑 A：公开契约与表世界

- [x] 1. 固化三仓基线和兼容版本元组
  - 记录 `rinspace-web`、Mastodon fork、私有 `rinspace` 的准确提交、运行时版本、数据库版本和制品摘要。
  - 在 Mastodon fork 建立相对上游的补丁目录与升级检查表，区分可上游化、Rinspace 专有和必须长期维护的补丁。
  - 定义世界契约版本、共享壳层版本和两套 runtime 版本的兼容规则；不允许使用 `latest` 或未固定分支。
  - 产出只读基线报告，不改写或删除现有工作树。
  - _Requirements: R14, R15, R19_

- [x] 2. 建立机器可读的世界路由契约
  - 在 `rinspace-web` 增加带 schema 和版本号的 route contract，逐类声明首页、账号、标签、帖子、单面页面和协议路由。
  - 实现纯函数式 world resolver：解析当前世界、生成当前世界首页、判断双面资源、计算 Logo 翻面目标和规范 URL。
  - 明确 outer URL 省略世界参数、inner URL 使用 `?world=inner`，并保证其他允许的查询参数不会被意外丢弃。
  - 为全部现有路由建立覆盖性测试；新增未分类页面时让 CI 失败，禁止依靠全局 catch-all 猜测 runtime。
  - _Requirements: R1, R2, R3, R10, R11, R12, R13, R14, R19_

- [x] 3. 发布框架无关的共享 `world-shell`
  - 从公开前端提取顶栏、Logo/文字行为、世界上下文、搜索入口和视觉 token，保持 React 19 peer dependency。
  - 通过 ports 注入导航、认证摘要、搜索、发布、通知和错误处理，不直接依赖 React Router、Redux、CloudBase 或 Mastodon initial state。
  - 命名空间化 CSS、字体和图标资源，防止两个 runtime 的全局样式互相污染。
  - 提供最小接入示例、API 文档、变更日志和兼容性测试。
  - _Requirements: R1, R2, R3, R6, R14, R19_

- [x] 4. 在 `rinspace-web` 接入世界壳层
  - 为 Router 7 和现有认证/搜索能力实现 outer adapter，替换重复顶栏逻辑。
  - 将 Logo 和 `Rinspace` 文字拆成两个独立、可键盘操作且有明确无障碍名称的控件。
  - 文字始终回到当前世界首页；Logo 在双面资源上翻到对应页面，在单面资源上回到相反世界首页。
  - 搜索、标签和站内导航默认留在当前世界，只有显式翻面动作才能跨世界。
  - _Requirements: R1, R2, R3, R4, R6, R11, R19_

- [x] 5. 实现页面级左右翻转转场
  - 使用同源 cross-document View Transition 表达两个世界的 Y 轴左右翻面，顶栏保持稳定、主体内容参与转场。
  - 对不支持 View Transition、资源加载失败和 `prefers-reduced-motion` 提供无动画回退。
  - 明确前进、后退、刷新、直接打开链接时的方向、焦点、滚动和历史栈行为。
  - 在桌面和移动端验证无闪白、无重复顶栏、无误触和无晕动障碍。
  - _Requirements: R1, R2, R3, R19_

- [x] 6. 收敛表世界信息架构
  - 让首页优先呈现书籍、博客和知识标签，维持安静、可阅读的内容密度。
  - 保留讨论、问答和动态入口、路由与历史数据，但不把它们冒充里世界帖子或强制迁移。
  - 为 `/@username` 和绑定标签提供表世界视图，与里世界共享身份或标签事实但使用不同内容编排。
  - 检查文章、书籍、搜索、错误页等单面页面的 Logo 回退目标。
  - _Requirements: R2, R3, R4, R6, R11, R13_

- [x] 7. 完成公开 Demo 和可消费制品
  - 用合成数据展示两个世界、账号双面、标签双面、单面页面回退、错误 slug 和降级状态，不访问私有 API 或生产数据。
  - 发布 versioned route contract、`world-shell` 包、校验和、许可证信息和最小 SBOM。
  - 更新 README：三大系统的本地安装、Node/pnpm 安装、常见失败处理、Codex 部署提示词、贡献与跨仓消费流程。
  - 增加制品安装验证，证明从干净环境可以只依赖公开仓库完成 Demo。
  - _Requirements: R1, R2, R3, R4, R6, R11, R14, R19_

### 里程碑 B：严格本地的 Mastodon 里世界

- [x] 8. 建立三层严格本地模式
  - 增加不可由普通管理员误开的 local-only feature gate，关闭远端账号/帖子解析、搜索、抓取、展示和关注。
  - 禁用 ActivityPub inbox/outbox、投递 worker、WebFinger/NodeInfo 等公网联邦入口，同时保留代码和内部命名空间供未来独立规格评估。
  - 在边缘规则和网络出口阻断联邦流量，对被拒请求、队列和出口建立零基线监控与告警。
  - 为 REST、streaming、后台任务和管理操作建立负向测试，证明本地模式不会静默触发远端访问。
  - _Requirements: R5, R12, R16, R17, R19_

- [x] 9. 实现稳定帖子路由和 slug 规范
  - 在 Rails、REST 返回、前端链接、分享、通知、搜索结果和元数据中统一生成 `/p/:id/:slug`，同时支持短地址 `/p/:id`。
  - 仅按稳定 status ID 定位；slug 缺失或错误仍显示原帖，并把 canonical 指向当前正确 slug。
  - 实现已确认的 slug v1 规范和跨 Ruby/TypeScript 共享 fixture，敏感或受限内容不得从 slug 泄漏。
  - 让旧 `/@username/:statusId` 及其 `/embed` 形式明确返回 404，不重定向、不继续生成；ActivityPub URI 保持协议语义不变。
  - 处理回复、引用、repost、媒体、投票、编辑历史和已删除/受限帖子等对象的正确落点。
  - _Requirements: R5, R10, R12, R13, R16, R19_

- [x] 10. 在 Mastodon fork 接入共享顶栏和里世界布局
  - 通过固定版本制品消费 `world-shell`，为 Router 5、Redux、initial state、发布框、通知和会话实现 inner adapter。
  - 将 Mastodon 原有主要导航重组为里世界布局：桌面侧栏与信息流、移动底栏，同时避免出现第二套站点顶栏。
  - 实现首页、账号和绑定标签的双面翻转；帖子、列表、通知、设置等单面页面翻回表世界首页。
  - 保留 Mastodon 完整本地能力：回复、repost、like、bookmark、分享、引用、媒体、投票、CW、可见性、mentions、编辑历史、列表、通知、关注请求、block、mute、report 和管理。
  - _Requirements: R2, R3, R5, R6, R11, R14, R19_

- [x] 11. 修正里世界客户端路由、Service Worker 和实时链路
  - 让客户端所有帖子、账号、标签和通知链接遵守新 route contract，不再生成上游旧式帖子 URL。
  - 把 Mastodon 根页面离线缓存改为 `/?world=inner`，限定 fetch 缓存只覆盖允许的 Mastodon 资产与媒体，避免缓存表世界 `/`。
  - 让 push 通知打开 `/p` 或明确的 inner URL；验证 streaming、分页、返回、刷新和断网恢复。
  - 对每次上游升级执行路由清单与 Service Worker 回归，新增上游对象类型必须先完成世界分类。
  - _Requirements: R1, R3, R5, R10, R11, R12, R13, R14, R19_

### 里程碑 C：统一身份、资料、标签与关注

- [x] 12. 建立稳定主体绑定和一键 SSO
  - 由 Rinspace Identity/Control Plane 预创建并绑定本地 Mastodon account，使用不可变 subject 作为跨系统主键。
  - 配置 OIDC 一键进入里世界；发生 handle、邮箱或已有账号冲突时 fail closed，不使用 Mastodon 自动追加后缀创建第二身份。
  - 定义首次进入、已登录、退出、停用、注销、封禁和绑定修复状态机，以及短期凭据和审计边界。
  - 禁止浏览器持有私有控制面凭据，并验证回调、CSRF、重放和错误恢复。
  - _Requirements: R6, R7, R8, R12, R16, R17, R19_

- [x] 13. 统一个人资料投影和 handle 生命周期
  - 以 Rinspace Identity 为本地 subject、当前 handle、头像和资料的权威来源，定义字段映射、长度差异、清洗和传播顺序。
  - `/@username` 在两个世界显示同一账号事实和同一粉丝关系，但各自组织知识内容与社区内容。
  - 实现改名 saga：新 handle 生效后旧 `/@username` 立即 404、不重定向、不永久保留；旧 handle 回到正常可注册池。
  - 为事件丢失、部分失败、重复投递和人工修复提供幂等消费、对账任务和审计记录。
  - _Requirements: R6, R7, R8, R15, R16, R17, R19_

- [x] 14. 建立知识标签与 Mastodon hashtag 绑定
  - 使用稳定 Rinspace tag ID 绑定 Mastodon tag ID/规范名称，支持显式创建、解绑、改名和冲突处理。
  - 标签点击始终留在当前世界；只有 Logo 才在已绑定标签间翻面，未绑定标签按单面页面处理。
  - 不因出现同名 hashtag 自动创建知识标签，避免垃圾内容污染表世界知识图谱。
  - 提供管理员预览、迁移、对账和回滚工具。
  - _Requirements: R3, R11, R15, R16, R19_

- [x] 15. 将关注关系迁为单一事实源
  - 以 Mastodon relationship engine 作为社交关注唯一事实源，按稳定 identity ID 映射现有本地关注关系。
  - 设计导入、锁定旧写入口、增量追平、切换读路径和回滚的完整时序，保留锁账号与关注请求语义。
  - 将 Gitea User Follow 降为兼容投影并持续对账；Star/Watch 保持原语义，不混入粉丝图。
  - 输出匿名化差异报告并处理孤儿、重复、自关注、封禁和停用账号。
  - _Requirements: R6, R7, R9, R15, R16, R19_

### 里程碑 D：本地社区、推荐与浏览量

- [x] 16. 把发帖互动接入内容治理状态机
  - 在发帖、回复、引用、媒体、投票、资料和第三方 API 等所有写入口执行一致的账号状态与内容门禁。
  - 接入审核、举报、申诉、屏蔽、限流、证据留存和管理员操作审计，避免只在 UI 层阻止写入。
  - 明确公开、未列出、仅关注者和私信的读取、搜索、推荐、计数与分享边界。
  - 建立机器审核不可用时的 fail-closed 或受控降级策略，并验证越权与绕过路径。
  - _Requirements: R5, R7, R12, R16, R17, R19_

- [x] 17. 接入 Gorse 推荐后端
  - 由 Mastodon 生成本地候选集并执行可见性、审核、block/mute 和账号状态过滤；Gorse 只排序，不成为内容权限权威。
  - 使用 `mastodon-status:<id>` 作为 item ID，处理创建、编辑、删除、降权和可见性变化的幂等同步。
  - 只允许公开、可发现且审核通过的本地帖子进入共享候选；未列出、仅关注者、私信和远端内容不得进入。
  - 由服务器调用 Gorse，浏览器不直连；定义超时、空结果、冷启动、匿名请求和服务故障的非个性化回退。
  - _Requirements: R5, R12, R16, R17, R18, R19_

- [x] 18. 实现“推荐 / 正在关注”信息流和用户控制
  - 里世界首页默认“推荐”，同时提供严格按时间排列的“正在关注”，并按账号记忆最近选择。
  - 提供关闭个性化推荐的显著入口；关闭后移除推荐页并默认进入正在关注，不能仅停止部分信号。
  - 提供非个性化选择、推荐原因说明、兴趣标签查看/删除和清除推荐画像能力。
  - 将 like、repost、reply、bookmark、follow 和合格阅读信号按最小化原则反馈，记录用途与保留期限。
  - _Requirements: R5, R16, R17, R18, R19_

- [x] 19. 实现可解释的帖子浏览量
  - 为 `status_stats` 增加原子递增的 `views_count`，扩展 REST Status 和 TypeScript 类型；不创建持久化逐次浏览事件表。
  - 增加认证后的本地计数端点：页面可见且卡片至少 50% 展示 1 秒，或详情停留 1 秒后才发送。
  - 使用 Redis 对 viewer/status/session 做 5 分钟 HMAC 技术去重，再由 Sidekiq 更新总浏览次数；预加载、SSR、bot、embed 和健康检查不得计数。
  - 公开和未列出帖子可展示；仅关注者仅向获授权用户展示；私信隐藏。产品文案只称“浏览次数”，不称独立访客。
  - 将展示计数与推荐阅读信号分离；关闭个性化后不得继续发送推荐阅读信号。
  - _Requirements: R5, R12, R16, R17, R18, R19_

### 里程碑 E：私有集成、迁移和上线门禁

- [x] 20. 实现同源 World Gateway
  - 从 versioned route contract 生成网关路由表，先区分静态资源/API/streaming/协议路由，再按页面路径与显式世界选择 runtime。
  - outer `/` 与 inner `/?world=inner` 在同一域名工作；账号和标签按世界分发，`/p` 始终进入 Mastodon，单面页面不被错误翻译。
  - 非法 world 值、未知路径和已废弃旧式帖子路径返回明确错误，不使用兜底代理把请求送进错误 runtime。
  - 保持真实客户端信息、CSP、cookie 范围、缓存键和压缩语义，验证不会跨世界缓存 HTML 或泄漏认证状态。

- [x] 21. 建立三仓本地开发和锁定发布流水线

  - 在跨仓 CI 中安装已发布制品而非复制源码，运行契约、数据库迁移兼容性和最小同源冒烟检查。
  - 发布 Mastodon fork 对应 AGPL 源码、许可证和修改说明；为每个组合版本准备可验证的回滚制品。

- [x] 22. 演练身份、标签和关注迁移

## 4. 完成定义

1. 所有任务均有可审计的实现、验证记录与回滚说明；
